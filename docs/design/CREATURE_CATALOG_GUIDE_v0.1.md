## Art pipeline (planning gate; Codex does not yet need to implement)

1. **Archive source:** retain original unmodified image and any layered pixel-editor masters. Record editor/tool, approximate creation date and owner-provided provenance. Never overwrite original.
2. **Sprite segmentation:** use expected grid cell centers and manually inspect each crop at nearest-neighbor 8× zoom. Gridline/light-lime backgrounds are not sprites. Some outlines/creature highlights may be close in color to the background; automatic chroma-key alone can erase artwork.
3. **Remove background:** create true alpha PNGs for each ID and store a checkerboard QA preview, with transparency verified on light, dark, green and purple backdrops. Retain shadow/contact mark separately if needed.
4. **Canonical pivots:** choose the foot/bottom contact point per creature, except floating creatures which use body center plus authored hover offset. Store pivots and bounding box, not a fixed crop assumption.
5. **Native resolution:** document true working sprite pixels and cell crop bounds. Current combined sheet dimensions include separators/margins, so do not pretend exactly 85×83 native sprite source size or apply bilinear upscaling.
6. **Overworld states:** front sprite usable for first encounter. Author new side/back idle and follow-cycle frames consistent with hand-drawn original pixel scale. Rotate billboards only within proven visibility constraints; a single sprite card is not full 360° animation.
7. **Battle states:** front idle, anticipation, attack, hurt, status, faint; choose 2–6 authored frames per action after pilot creature's workload assessment.
8. **Metadata and pack:** record `sourceCell`, `pivotPx`, `frames`, `fps`, `collisionProfile`, `worldScale`, `affinity`, `biomes`, `sourceRights`; pack into per-zone atlases after visual QA. Do not bundle all 100 creatures into memory for first forest level.
9. **Performance validation:** test 1, 8 and 32 moving sprites near layered foliage; profile RAM, CPU, transparency overdraw on low-end Windows and Android.
10. **Commercial asset ledger:** original drawn user-owned artwork, acquired third-party media, music and future generated assets must be tracked separately. Original-user-art claim is not a blanket grant for external fonts/music/textures.

## Original pixel-editor source unavailable — 2026-10-20 owner clarification

The user personally hand-created and owns the original pixel art; **it is not AI-generated**. The original editable Aseprite project is no longer available because it was on a broken desktop. **Do not make obtaining that file a prerequisite** to creation of sprites or 2.5D engine testing. Use the surviving flattened combined 10×10 sprite image already indexed above as source, retain an unmodified checksum-backed archival copy, segment all 100 cells by measured grid boundaries, then **manually inspect** transparency masks and outlines. In particular lime-colored pixels in the original creatures can be erased by naive global chroma-keying; manually retouch masks without changing creature design. Generate new per-species editable layered masters from cleaned transparent crops, then author needed animations/side views separately. The lost historical layers cannot be automatically recovered from flat pixels. Optional old SSD/HDD recovery may help but is **not** required. Full procedure: `docs/planning/HARDWARE_AND_SPRITE_RECOVERY_INTAKE_v0.1.md`. No art extraction has been executed under the present planning-only request.
